# CrisisLens

**Multimodal triage of disaster social media posts.** CrisisLens reads a post's text and photo together, flags the
ones responders need to see, sorts them by type of need, explains why, and puts them on a map with short, cited
area summaries.

**Live demo:** [huggingface.co/spaces/kshitid/crisislens](https://huggingface.co/spaces/kshitid/crisislens) · **Demo video:** _add link_

![results](figures/main_results.png)

## Why

During hurricanes, floods, and wildfires, thousands of posts appear every hour. A few show trapped people, collapsed
bridges, or rescue requests; most are noise. Text alone misses what the photo shows, and photos alone miss what the
text says. CrisisLens learns, post by post, how much to trust each.

## Results

CrisisMMD v2.0 test split (official agreed-label splits), macro-F1, mean ± std over 3 seeds. Macro-F1 is the headline
metric because the classes are imbalanced. Generated by `python -m crisislens.report`.

| Model | Informative | Humanitarian | Damage | Urgent recall |
| --- | --- | --- | --- | --- |
| TF-IDF + LR (text) | 0.810 | 0.657 | 0.489 | 0.722 |
| BERTweet (text) | 0.860 ± 0.000 | 0.740 ± 0.019 | 0.460 ± 0.014 | 0.918 ± 0.013 |
| CLIP (image) | 0.879 ± 0.008 | 0.757 ± 0.017 | **0.590** ± 0.012 | 0.858 ± 0.027 |
| Late fusion (avg probs) | **0.919** ± 0.001 | 0.814 ± 0.020 | 0.572 ± 0.015 | **0.941** ± 0.019 |
| Concat fusion | 0.908 ± 0.008 | 0.819 ± 0.024 | 0.581 ± 0.027 | 0.907 ± 0.024 |
| Gated fusion, modality dropout 0.15 | 0.908 ± 0.009 | 0.800 ± 0.022 | 0.547 ± 0.026 | 0.900 ± 0.014 |
| **Gated fusion, modality dropout 0.4 (deployed)** | 0.903 ± 0.013 | **0.824** ± 0.020 | 0.556 ± 0.010 | 0.921 ± 0.017 |
| Gated fusion (dropout 0.15), unseen disaster | 0.806 | 0.625 | 0.341 | 0.750 |

What the numbers say:

- **The photo helps.** The deployed model beats text-only BERTweet by +0.084 humanitarian macro-F1. Fusion models are
  within noise of each other on humanitarian; gated fusion is deployed because its gate shows how much each
  prediction leaned on the photo.
- **Damage is a visual task.** Image-only CLIP (0.590) matches or beats every fusion model on damage severity.
- **Fixing the missing-photo case.** With modality dropout 0.15, gated fusion fell to 0.588 humanitarian macro-F1 when
  the photo was hidden, far below BERTweet's 0.740. Raising dropout to 0.4 lifted that to 0.642 *and* improved the
  full-input score (0.800 → 0.824). Posts without a photo are routed to BERTweet, so each post gets the better model
  ([chart](figures/missing_photo.png)).
- **Calibrated and tuned for recall.** Temperature scaling cuts expected calibration error by 45–60% per task
  (damage 0.132 → 0.055). The urgent flag, with its threshold set on dev, keeps 91.4% recall at 85.1% precision on test.
- **Unseen disasters are harder.** Trained without one disaster and tested only on it, scores drop (damage 0.341).
  This is a single run, so read it as one example, not an estimate.
- **Serving.** int8 ONNX: 380 MB instead of 893 MB, 11.8 ms instead of 31.5 ms (PyTorch) per post on CPU, and test
  macro-F1 within 0.01 of full precision (0.916 / 0.829 / 0.572). Every export is scored end to end on the test split;
  that check caught a tokenizer save bug that would have silently collapsed the text model to one class.

Missing-modality and calibration numbers are for the seed-42 model. Figures are in [`figures/`](figures) and
[`notebooks/02_results.ipynb`](notebooks/02_results.ipynb).

## How it works

```mermaid
flowchart LR
    T[Post text] --> B[BERTweet]
    I[Post photo] --> C[CLIP ViT-B/32]
    B --> PT[project]
    C --> PI[project]
    PT --> G{{gate g}}
    PI --> G
    G --> F["h = g·text + (1−g)·image"]
    F --> H1[Informative?]
    F --> H2[Need type]
    F --> H3[Damage severity]
```

- **Encoders.** BERTweet (pretrained on 850M tweets) for text; the vision half of CLIP for photos. Both fine-tuned.
- **Gated fusion.** A learned gate mixes the two per dimension and per post. Its average, *image reliance*, says how
  much each prediction leaned on the photo. Missing photos get zero image weight.
- **Multi-task heads.** One shared representation, three heads, losses masked where a post has no label for a task.
- **Modality dropout.** During training, text or image is hidden 40% of the time, so the model still works with one.
- **Routing.** Posts without a photo go to a text-only BERTweet model, which beats fusion when the photo is missing.
- **Leakage guard.** A post that is in dev/test for any task is never trained on for any task.
- **Calibration and flagging.** Temperature scaling on dev; a post is flagged urgent when P(people affected, rescue, or
  damage) passes a threshold chosen on dev for 90% recall.
- **Explanations.** Integrated Gradients (Captum) for words during analysis; occlusion for words and image regions in
  the live demo.
- **Serving.** Exported to ONNX and quantized to int8 (per-channel, embeddings kept fp32); the demo and API run on
  CPU without PyTorch. Inference applies the same tweet normalization as training.

## Reproduce it

Tested on a MacBook M4 Pro (16 GB). PyTorch uses the Apple GPU (MPS) automatically.

```bash
# 1. Environment (Python 3.11)
python3.11 -m venv .venv && source .venv/bin/activate
pip install -e ".[train,serve,geo,track,dev]"
python -m spacy download en_core_web_sm
nbstripout --install                      # keep notebook outputs (tweets) out of git
pytest -q                                 # 50 tests, about a minute

# 2. Data: download from https://crisisnlp.qcri.org/crisismmd.html into data/crisismmd/
#    CrisisMMD_v2.0.tar.gz  +  crisismmd_datasplit_agreed_label.zip
python scripts/check_data.py --data-dir data/crisismmd

# 3. All experiments (resumable; run overnight, plugged in)
caffeinate -i bash scripts/run_experiments.sh       # add WANDB=1 to log to Weights & Biases
caffeinate -i bash scripts/run_followup.sh          # deployed model (modality dropout 0.4) + text fallback

# 4. Export the deployed model
python -m crisislens.export_onnx --run outputs/fusion_gated_md40/seed_42 --out exported/
python -m crisislens.export_onnx --run outputs/text_bertweet_kept/seed_42 --out exported/text_fallback/  # posts without an image

# 5. Results figures: run notebooks/02_results.ipynb
```

Quick smoke test before the long run: `python -m crisislens.train --config configs/fusion_gated.yaml --max-train-batches 20 --epochs 1`.

## Demo

The demo replays **Hurricane Delphine**, a fictional storm with posts written for this project and public-domain
photos, so no CrisisMMD content is published (see [docs/DATA.md](docs/DATA.md)).

```bash
python scripts/build_scenario.py fetch-images          # public-domain photos + credits; check contact_sheet.jpg
export GEMINI_API_KEY=...                              # optional; template summaries without it
python scripts/build_scenario.py build --model exported/
MODEL_DIR=exported streamlit run app/streamlit_app.py  # local preview

export HF_TOKEN=hf_write... HF_READ_TOKEN=hf_read...
python scripts/publish_model.py --repo <user>/crisislens-model            # private model repo
python scripts/deploy_space.py --space <user>/crisislens --model-repo <user>/crisislens-model
```

API: `MODEL_DIR=exported uvicorn service.api:app --port 8000`, then `POST /classify` with
`{"posts": [{"text": "...", "image_base64": "..."}]}`.

## Data, limitations, responsible use

Trained on [CrisisMMD v2.0](https://crisisnlp.qcri.org/crisismmd.html) (research use only; contents kept
confidential, model kept private). The data is English tweets from 2017, the demo posts are cleaner than real ones,
and location extraction is approximate. Known failure cases: a post about a rare need (a missing person, post p22 in
the demo replay) can go unflagged, because such posts are rare in the training data; and a photo that contradicts the
text can pull the prediction toward what the photo shows. CrisisLens is a triage aid: it ranks what people look at
first and never decides who gets help. Details: [docs/DATA.md](docs/DATA.md).
